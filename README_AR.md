# حزمة إعداد وتحديث رام

هذه الحزمة تجمع أحدث ملفات واجهة رام المتاحة في الأرشيف، ومصدر التشغيل السحابي المحفوظ، مع فصل واضح بينهما حتى لا يُستبدل خادمك العامل بنسخة غير متوافقة.

## محتويات الحزمة

- `app/src/main/assets/app.js` و`app/src/main/java/com/ram/agent/MainActivity.java`: ملفا واجهة التطبيق من تحديث استعادة زر Serper.
- `server/cloud-autopilot/`: مرحلة التشغيل السحابي الأولى، بما فيها `server.js` والوحدات التابعة والاختبارات.
- `RAILWAY_VARIABLES_CHECKLIST.md`: أسماء الإعدادات المطلوبة وطريقة مشاركة لقطة آمنة.
- `COMPATIBILITY.md`: توافق الواجهة مع الخادم وما لم يُنفذ بعد.

## تحديث التطبيق في مستودع GitHub

انسخ الملفين الأولين إلى المسارين نفسيهما في مستودع Android لديك، ثم راجع التغييرات واعمل Commit وابنِ APK من سير عمل المستودع المعتاد. احتفظ ببقية ملفات التطبيق كما هي، وخصوصًا `index.html` الذي يجب أن يحمّل `app.js`. لا تتضمن هذه الحزمة `index.html` أو ملفات Gradle أو Manifest أو مفاتيح توقيع APK، لذلك لا تُعد مشروع Android كاملاً ولا تنتج APK بمفردها.

قبل الدمج، احتفظ بنسخة من ملفات المستودع الحالية. لا تستبدل `server.js` الحالي بملف مرحلة التشغيل السحابي من هذه الحزمة؛ راجع `COMPATIBILITY.md` أولاً. قد تكون نسخة الخادم الحالية في Railway أحدث من الأرشيف هنا.

## تشغيل مرحلة الأتمتة السحابية

المجلد `server/cloud-autopilot/` هو خدمة مستقلة للمرحلة الأولى، ومفصول عن كود Android. عند دمجها في مستودع الخادم، انسخ محتوياته إلى جذر خدمة Railway (أو إلى مساراتها المعتمدة) مع الحفاظ على ملفات الوحدات و`package.json` معاً. لا تنشر هذه المرحلة فوق الخادم العامل دون دمج مسارات API المبيّنة في `COMPATIBILITY.md`.

تحتاج المرحلة إلى Volume دائم في Railway مركب على `/data` (أو المسار الفعلي الذي تختاره)، ومتغير `RAM_API_TOKEN`، ومفتاح بحث واحد على الأقل (`SERPER_API_KEY` أو `TAVILY_API_KEY`). أضفت دعم `RAM_DATA_DIR` الموجود في لقطتك لمسار بيانات الأتمتة. تفاصيل بقية الأسماء الظاهرة في قائمة التحقق. بعد النشر، صفحة التحكم هي `/automation/control`.

هذه المرحلة تبحث دوريًا وفق فرصة مرجعية يختارها المستخدم وتعدّ سجلات ومسودات للمراجعة. لا تتقدم تلقائيًا للوظائف، ولا تسلّم مخرجات، ولا تضمن عشر مهام أو دخلاً يوميًا. أبقِ مراجعة المالك مطلوبة قبل التواصل أو التقديم أو الالتزام التجاري.

## اختبارات أُجريت

- نجح `node --check` لملف الواجهة `app.js` وملفي الخادم `server.js` و`cloud-automation.js`.
- نجح `npm test`: الاختبارات الثلاثة المرفقة اجتازت، ومنها اختبار `RAM_DATA_DIR`.
- لم يُبنَ APK ولم يُختبر نشر Railway، لأن مستودع التطبيق الكامل وبيانات النشر غير موجودة ضمن هذه الحزمة.

## الخصوصية والمال

لا تضف كلمات مرور الحسابات أو رموز التحقق أو مفاتيح السحب إلى رام أو GitHub. لا تشارك ملف المفاتيح أو قيمها. التداول والتحويلات والسحب والشراء تظل خارج التنفيذ الآلي؛ وأي عملية مالية تتطلب قرارك المباشر خارج رام. قد تحتوي صور الشاشة على بيانات حساسة؛ أخفِ القيم السرية قبل إرسال لقطة Railway.
