# تحديث رام: توسيع البحث وإصلاح عنوان الخادم

## الملفات

انسخ الملفات الثلاثة إلى المسارات نفسها في مستودع RAM-Agent:

- `app/src/main/assets/app.js`
- `app/src/main/java/com/ram/agent/MainActivity.java`
- `server/server.js`

## ما يتغير

- أمر «ابدأ العمل» يبحث في الترجمة والهندسة والمواقع والإعلانات واللوجستيات والتوريد والبحث، مع توسيع كلمات البحث لتشمل تصميم المنتجات والأجهزة و3D والسيارات.
- بعد انتهاء البحث على الهاتف، يختار رام أفضل نتيجة مؤهلة ويبدأ سجل المهمة ويرسله إلى العامل السحابي. لا تُحفظ نتائج البحث الأخرى في التخزين السحابي.
- يوجّه إعداد مسودات السحابة المخرجات لتكون عملية وقابلة للنسخ، مثل صفحات HTML ومواد الإعلان وSVG أو OpenSCAD عندما تسمح المهمة والمعلومات بذلك.
- يُحدّث التطبيق عنوان Railway المحفوظ القديم إلى `https://ram-agent-production-2ee8.up.railway.app`، ويعيد المحاولة على هذا النطاق إذا تعذر حل DNS للنطاق المحفوظ.

## بعد رفع الملفات

1. استبدل الملفات الثلاثة في GitHub بالمسارات أعلاه.
2. انتظر نجاح نشر Railway لخدمة `server` ونجاح مهمة GitHub التي تبني APK.
3. ثبّت APK الجديد على الهاتف. تحديث الخادم وحده لا يغيّر التطبيق المثبت.
4. افتح رام واكتب حرفيًا: `ابدأ العمل`.
5. اترك رام مفتوحًا حتى ينتهي البحث وتظهر رسالة أن المهمة حُفظت في السحابة. بعد تأكيد الحفظ، يستطيع العامل متابعة تجهيز المسودة عند إغلاق التطبيق ما دامت Railway والتخزين الدائم يعملان.

## حدود التنفيذ الحالية

البحث الأولي المتعدد الأقسام يبدأ من التطبيق، لذلك يجب أن يبقى مفتوحًا حتى يرسل المهمة المختارة للخادم. بعد ذلك، العامل السحابي يجهّز خطة أو عينة أو مسودة؛ ولا يرسل عروضًا أو ينشئ حسابات منصات أو يوقع عقودًا أو يرفع تسليمات أو يحرك أموالًا. الإشعارات الحالية ليست إشعارات دفع من الخادم إلى الهاتف المغلق. هذه الخطوات تحتاج واجهات رسمية وصلاحيات مصادقًا عليها لكل منصة، وإشعارًا سحابيًا مثل Firebase قبل وصول تنبيه والهاتف مغلق. لا يوجد ضمان دخل أو مبلغ يومي.
