# تحديث n8n لرام — v1

هذه الحزمة تضيف اختبار اتصال آمن بين رام وn8n. لا تحتوي مفاتيح أو كلمات مرور.

## ملفات التحديث
انسخ الملفات مع الحفاظ على المسارات داخل مستودع GitHub:
- `server/server.js`
- `app/src/main/assets/app.js`
- `app/src/main/java/com/ram/agent/MainActivity.java`

## إعداد n8n
1. أنشئ Workflow جديدًا وأضف عقدة **Webhook**.
2. اختر **POST**، وأضف **Header Auth** credential:
   - اسم الترويسة: `X-RAM-Webhook-Secret`
   - القيمة: سر عشوائي طويل (24 حرفًا على الأقل). لا تستخدم كلمة مرور حسابك.
3. اجعل الاستجابة **Immediately**، ثم أضف خطوة آمنة لا تنفذ عملاً، مثل تسجيل الحدث أو فحصه. حدث الاختبار الذي يرسله رام اسمه `ram.connection_test`.
4. انشر/فعّل الـ Workflow وانسخ **Production URL** من عقدة Webhook. عنوان الاختبار المؤقت لا يعمل بعد إغلاق وضع الاستماع.

## إعداد Railway
في خدمة RAM-Agent > Variables أضف:
- `N8N_WEBHOOK_URL` = Production URL من n8n
- `N8N_WEBHOOK_SECRET` = نفس القيمة التي وضعتها في Header Auth

احتفظ بالسر في Railway وn8n فقط. لا تضعه في GitHub أو داخل التطبيق أو ترسله في المحادثة. بعد حفظ المتغيرات انتظر إعادة نشر الخادم.

## اختبار الاتصال
بعد رفع الملفات:
1. ادفع التحديث إلى GitHub. انتظر نجاح بناء APK من GitHub Actions.
2. حدّث خادم Railway إذا لم يبدأ النشر تلقائيًا.
3. ثبّت APK الجديد، وافتح الإعدادات > الحسابات والأدوات > أتمتة n8n.
4. اضغط **اختبار اتصال n8n** ووافق على إرسال الاختبار. في n8n راجع **Executions** للتأكد من وصول الحدث.

الاختبار يرسل حدثًا واحدًا عند ضغط الزر وموافقتك. لا يرسل بريدًا ولا يسلّم ملفات أو ينفذ طلب عمل. هذه المرحلة تثبت الاتصال فقط؛ سنضيف أحداث سير العمل (مثل تغيّر حالة المهمة ومراجعة التسليم) على مراحل مع موافقة واضحة قبل الإجراءات الخارجية.

## تنبيه إصدار
هذا تحديث لخادم Railway وتطبيق Android معًا. لا تستبدل مجلدات المشروع كلها؛ استبدل الملفات الثلاثة المحددة فقط حتى تحتفظ بباقي تحديثات الصوت والواجهة.
