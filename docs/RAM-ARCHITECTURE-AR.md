# إعادة هيكلة RAM إلى مساعد موثوق

## الهدف وحدوده

RAM تطبيق مساعد يستخدم نماذج وخدمات خارجية. وصفه بـ«عصبي» أو «حسي» يكون تجربة محادثة طبيعية، وليس ادعاء وعي أو إحساس بشري. موثوقية RAM تأتي من أدوات تعمل فعلًا، وذاكرة يملكها المستخدم، وتسجيل واضح لما نجح وما فشل، وطلب موافقة قبل أي إجراء مؤثر.

لا يمكن لأي خدمة سحابية أن تواصل العمل إذا انقطع الإنترنت عنها. يمكنها متابعة مهمة مقبولة في السحابة عندما يكون الهاتف مغلقًا، ما دامت خدمة Railway والجدولة والتخزين تعمل. الاستماع الصوتي الدائم على Android يحتاج خدمة أمامية ظاهرة بإشعار دائم وصلاحية ميكروفون؛ لا يوعد به كميزة مخفية أو غير محدودة.

## مسار تنفيذ تدريجي

### المرحلة 1 — الصدق والاستقرار

- توحيد شكل رد API: `ok`, `status`, `provider`, `requestId`, ورسالة مفهومة، مع إخفاء الأسرار.
- جعل لوحة الإعدادات تعرض: غير مهيأ، مهيأ، نجاح الاختبار، فشل الاختبار، وآخر وقت تحقق. لا تعرض «متصل» اعتمادًا على وجود اسم متغير فقط.
- إصلاح اختبارات الموصلات واحدًا واحدًا والتحقق من Railway logs بعد كل نشر.
- إضافة health/readiness منفصلين: صحة الخادم لا تعني أن Cloudflare أو n8n متصلان.

### المرحلة 2 — وكيل محادثة حقيقي

- مسار المحادثة: فهم → استرجاع سياق مسموح → اقتراح فعل من قائمة أدوات معرفة → فحص السياسة → تنفيذ عند السماح → تلخيص النتيجة بالدليل.
- لا يخترع نجاحًا أو دخلًا أو إرسالًا. يصرّح «لم أنفّذ» عند فشل الأداة، ويميّز بين «قبل n8n الطلب» و«اكتمل العمل».
- استخدام محادثة متعددة الأدوار مع حدود حجم، مهلة، إلغاء، ومراجع للنتائج؛ استبدال المزود لا يغير سلوك التطبيق.

### المرحلة 3 — مهام سحابية تستمر بعد إغلاق الهاتف

- عند قول «ابدأ»، ينشأ Job في الخادم، ثم يعيد الخادم رقمًا وحالة أولية.
- عامل سحابي دائم يعالج الطابور، ويحدّث التقدم والأخطاء ومحاولات الاستعادة.
- عند الانتهاء يرسل Push notification إلى الجهاز. هذا يتطلب إعداد FCM/بديل، صلاحية الإشعارات، واتصال الهاتف بالإنترنت كي يستقبلها.
- عند انقطاع اتصال العامل بالإنترنت، تتوقف عمليات المزود الخارجية وتظل المهمة معلقة أو تفشل بوضوح؛ لا يوجد تنفيذ سحابي بلا اتصال بالمزود.

### المرحلة 4 — ذاكرة شخصية وصوت اختياري

- نموذج بيانات للأشخاص والعلاقات والتفضيلات، بمراجعة المستخدم وتعديل/حذف، وتشفير وتحديد مدة الاحتفاظ.
- تحية شخصية اختيارية وقابلة للإيقاف؛ تجنب إدراج معلومات صحية أو أسماء أشخاص في إشعار ظاهر قبل ضبط الخصوصية.
- الصوت المستمر ميزة Android منفصلة: foreground service وإشعار ظاهر وتحكم إيقاف. عند إغلاقه يعود التطبيق للوضع العادي؛ لا يستمع سرًا.

### المرحلة 5 — تكامل العمل وتحقيق الدخل

- ابدأ بترشيح فرص مناسبة، تلخيص شروطها، وصياغة مسودة عرض مع ميزانية ووقت تقديريين.
- لا يقدم RAM تلقائيًا على منصات العمل ولا يراسل الشركات دون مراجعة صريحة لكل تقديم أو رسالة، مع احترام شروط المنصة.
- لا يمكن ضمان 10 أعمال يوميًا أو دخل يومي؛ يقاس النجاح بمهام مكتملة ومقبولة ومدفوعة فعلًا، لا بعدد الطلبات المرسلة.

## معايير قبول قبل تسمية RAM موثوقًا

1. كل زر اختبار يُجري طلبًا حقيقيًا ويعرض رمز الحالة وسبب الفشل دون كشف المفتاح.
2. كل فعل خارجي له `requestId` وسجل نتيجة، ومنع للتكرار، وحالة نهائية قابلة للتحقق.
3. لا يعرض التطبيق «اكتمل» قبل تأكيد مصدر العمل أو مزود الخدمة.
4. المستخدم يستطيع إيقاف الصوت والجدولة ومسح الذاكرة وإلغاء مهمة جارية.
5. اختبار بناء Android واختبارات API ونشر تجريبي ناجح موثق، ثم اختبار من الهاتف على النسخة المنشورة.

## فصل الموجود عن المقترح

الملف `server/server.js` في هذه الحزمة هو إصلاح خادم n8n المحدد. هذا لا يبني وحده نظام ذاكرة طويل الأمد، أو عامل طوابير، أو استماع خلفي، أو إشعارات Push. هذه قدرات مستقلة يجب تنفيذها واختبارها على ملفات المشروع الكاملة قبل وصفها بأنها جاهزة.
